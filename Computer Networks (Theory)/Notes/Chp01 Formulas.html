Mathematical Models for Network Performance

Based on excerpts from Chapter 1, "Computer Networks and the Internet," this document details the key mathematical models and formulas used to analyze delay, loss, and throughput in packet-switched networks.

1. Total Nodal Delay

dnodal = dproc + dqueue + dtrans + dprop

Explanation

The total time a packet spends at a single network node (like a router) is the sum of four distinct types of delays. These are:

  • Processing Delay (dproc): The time it takes for the router to examine the packet's header, check for bit-level errors, and determine the packet's destination. This is typically in the range of microseconds or less in modern high-speed routers.
  • Queuing Delay (dqueue): The time the packet spends waiting in a queue (or buffer) before it can be transmitted onto the outgoing link. This delay is variable and depends on the network's congestion level.
  • Transmission Delay (dtrans): The time required to push all of the packet's bits onto the communication link. It's a function of the packet's size and the link's speed, not the distance it has to travel.
  • Propagation Delay (dprop): The time it takes for a bit to travel from the beginning to the end of the link. This is dependent on the physical distance of the link and the propagation speed of the medium (close to the speed of light).

Example

Imagine a packet arriving at a router. The router takes 10 microseconds (μs) to process the header (dproc). The network is busy, so the packet waits in a queue for 500 μs (dqueue). The packet is 1500 bytes long and is being sent over a 100 Mbps link, so its transmission delay is 120 μs (dtrans). The next router is 100 km away over a fiber-optic cable, resulting in a propagation delay of 500 μs (dprop).

The total nodal delay would be: 10 μs + 500 μs + 120 μs + 500 μs = 1130 μs or 1.13 milliseconds.

2. Transmission Delay

dtrans = L / R

Explanation

Transmission delay is the time it takes to place a packet onto the network link. It is calculated by dividing the packet's length (L), measured in bits, by the transmission rate of the link (R), measured in bits per second (bps).

  • L: Length of the packet in bits.
  • R: Transmission rate of the link (bandwidth) in bits per second.

Example

If you want to send a packet of 1,500 bytes over a 100 Megabits per second (Mbps) Ethernet link:

  • First, convert the packet length to bits: 1,500 bytes * 8 bits/byte = 12,000 bits.
  • The link rate is 100,000,000 bits per second.

The transmission delay is: dtrans = 12,000 bits / 100,000,000 bps = 0.00012 seconds, or 0.12 milliseconds.

3. Total End-to-End Delay (Conceptual Basis)

dend-to-end = N * (dproc + dprop) + L / R

Explanation

This formula provides a simplified model for the total time it takes for a single packet to travel from a source to a destination across a network with N links, assuming no queuing delay. It sums the processing and propagation delays for each of the N links and adds the single transmission delay for the packet. This specific formula assumes homogenous links where processing, propagation, and transmission rates are the same across the network.

  • N: Number of links between the source and destination.
  • dproc: Processing delay at each node.
  • dprop: Propagation delay on each link.
  • L: Length of the packet in bits.
  • R: Transmission rate of the links in bits per second.

Example

Consider a packet of 1,000 bytes traversing a path with 3 links (N=3). The processing delay at each router is 5 μs, and the propagation delay for each link is 20 μs. The packet size is 8,000 bits (1000 bytes * 8), and the link speed is 1 Gbps (1,000,000,000 bps).

First, calculate the transmission delay: 8,000 bits / 1,000,000,000 bps = 8 μs.

Now, calculate the end-to-end delay: dend-to-end = 3 * (5 μs + 20 μs) + 8 μs = 3 * (25 μs) + 8 μs = 75 μs + 8 μs = 83 μs.

4. Time to Transfer Multiple Packets

Total Time = 4 * L / R (for P=3 packets, 2 links)

Explanation

This specific case illustrates the time required to send 3 packets from a source to a destination through a single router (which involves 2 links). The formula highlights the pipelining nature of packet switching. The first packet's journey takes time, but subsequent packets follow closely behind. The generalized concept for sending P packets over N links often involves a formula structure of (P + N - 1) * (L/R) under certain assumptions. The provided formula (4 * L/R) for 3 packets over 2 links aligns with the simplified scenario where N=2 and P=3, resulting in (3+2-1) = 4 terms of L/R in some models.

Example

If a source sends 3 packets of 1,000 bytes each (L = 8,000 bits) over a path with one router and a uniform link speed of 10 Mbps (R = 10,000,000 bps):

The time to transmit one packet is L / R = 8,000 / 10,000,000 = 0.0008 seconds.

Using the provided formula, the total time is: Total Time = 4 * 0.0008 seconds = 0.0032 seconds, or 3.2 milliseconds.

5. Traffic Intensity

I = L * a / R

Explanation

Traffic intensity is a measure used to gauge how congested a network link is. It is the ratio of the rate at which data arrives to the rate at which data can be transmitted. For a stable system where the queue does not grow infinitely, the traffic intensity must be less than 1. When I > 1, the queue will grow without bound, leading to packet loss.

  • L: Average packet length in bits.
  • a: Average packet arrival rate in packets per second.
  • R: Link transmission rate in bits per second.

The term L*a represents the average rate at which bits arrive at the queue.

Example

Consider a link with a transmission rate (R) of 1 Mbps. Packets with an average length (L) of 1,000 bits arrive at an average rate (a) of 800 packets per second.

The traffic intensity is: I = (1,000 bits/packet * 800 packets/sec) / 1,000,000 bits/sec = 800,000 / 1,000,000 = 0.8.

Since I is 0.8 (which is less than 1), the link can handle the traffic on average, although temporary queuing may occur. If the arrival rate increased to 1,200 packets per second, the intensity would become 1.2, and the queue would grow indefinitely.

6. Queuing Delay Model

dqueue = (I * (L/R)) / (1 - I) (for I < 1)

Explanation

This formula provides an estimate for the average queuing delay under certain theoretical conditions (specifically, for an M/M/1 queue, which assumes random packet arrivals and service times). The formula shows that as traffic intensity (I) approaches 1, the queuing delay approaches infinity. This model is crucial for understanding how network performance degrades rapidly as a link nears its full capacity.

  • I: Traffic Intensity (must be less than 1).
  • L/R: The transmission delay of a single packet.

Example

Using the previous example where I = 0.8 and the transmission delay (L/R) is 1,000 bits / 1,000,000 bps = 0.001 seconds:

The average queuing delay is: dqueue = (0.8 * 0.001) / (1 - 0.8) = 0.0008 / 0.2 = 0.004 seconds, or 4 milliseconds.

If the traffic intensity increases to I = 0.95, the delay becomes: dqueue = (0.95 * 0.001) / (1 - 0.95) = 0.00095 / 0.05 = 0.019 seconds, or 19 milliseconds, showing a significant increase.

7. Bandwidth-Delay Product

Bandwidth-Delay Product = R * dprop

Explanation

The bandwidth-delay product estimates the maximum number of bits that can be "in flight" on a network link at any given time—data that has been sent but not yet acknowledged. It represents the volume of the "pipe" connecting two points. This metric is particularly important for performance tuning, especially in networks with high bandwidth and long delays (known as "Long Fat Networks" or LFNs), as it helps determine optimal buffer sizes and TCP window sizes.

  • R: Link rate in bits per second.
  • dprop: Propagation delay in seconds (often, the round-trip time is used for dprop in practical applications like TCP window sizing).

Example

Consider a geostationary satellite link with a bandwidth (R) of 100 Mbps and a round-trip propagation delay (dprop) of 500 milliseconds (0.5 seconds).

The bandwidth-delay product is: 100,000,000 bits/sec * 0.5 sec = 50,000,000 bits.

This means that 50 million bits (or 6.25 megabytes) of data can be in transit on the link at any moment. To fully utilize this link, the sender would need to be able to send this much data before stopping to wait for an acknowledgment.

8. Throughput (M Simultaneous Downloads)

Throughput = min{Rs, Rc, R/M}

Explanation

This formula determines the per-download throughput in a scenario where multiple (M) clients are downloading from a server, and they all share a common bottleneck link. The overall performance for each download is limited by the slowest part of its end-to-end path. The throughput will be the minimum of the server's upload speed, the client's download speed, or the share of the common link's bandwidth.

  • Rs: The transmission rate of the server's access link.
  • Rc: The transmission rate of the client's access link.
  • R: The transmission rate of the shared link.
  • M: The number of simultaneous downloads.

Example

A server has a 100 Mbps connection (Rs). There are 10 clients (M=10), each with a 20 Mbps connection (Rc). They are all downloading simultaneously and share a common network link with a total capacity of 50 Mbps (R).

The throughput for each client will be the minimum of:

  • The server's link rate: 100 Mbps
  • The client's link rate: 20 Mbps
  • The shared portion of the common link: 50 Mbps / 10 = 5 Mbps

In this case, Throughput = min{100, 20, 5} = 5 Mbps. The shared link is the bottleneck, and each user gets 5 Mbps of throughput for their download.
